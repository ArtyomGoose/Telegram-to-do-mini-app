# Проект: Telegram Mini App с контролем доступа

## Описание

Telegram Mini App (TWA) на React + Vite для управления ежедневными задачами и целями с синхронизацией в реальном времени через Firebase. Возможности:
- Управление задачами с отслеживанием выполнения и дедлайнами
- Цели / Vision Board с мозаичной раскладкой фотографий
- Нижняя панель вкладок (Задачи, Цели, Рутина)
- Прогресс-бары за день и за год (русская локализация)
- Контроль доступа: аутентификация по белому списку Telegram ID
- Синхронизация в реальном времени между устройствами
- Тёмная тема Telegram

## Технологический стек

- **Фронтенд:** React 18, Vite 7
- **Бэкенд:** Firebase Realtime Database + Python Telegram Bot
- **Интеграция бота:** Vercel Serverless Function (Python 3.12)
- **Стили:** CSS с переменными темы Telegram
- **Локализация:** Русский язык (даты, текст UI)

## Основные функции

### 1. Контроль доступа (белый список)

**Файл:** `twa/src/auth.js`

Три сценария аутентификации:

1. **Telegram Mini App:** ID пользователя извлекается из `window.Telegram.WebApp.initDataUnsafe.user.id` и проверяется против белого списка мгновенно.
2. **Браузер + сохранённый ID:** Если пользователь посещал приложение раньше, его ID извлекается из `localStorage.getItem('twa_browser_id')` и проверяется.
3. **Браузер + первое посещение:** Показывается форма входа, пользователь вручную вводит свой Telegram ID, затем проверяется против белого списка.

**Белый список:** В настоящее время захардкожен в `auth.js` как `ALLOWED_IDS = ['123456789', '987654321']`. Замените на реальные ID.

**Статусы аутентификации:**
- `null` → Проверяется статус
- `'allowed'` → Пользователь может использовать приложение
- `'denied'` → Показывается страница AccessDenied
- `'browser_login'` → Показывается форма входа

### 2. Нижняя панель вкладок

**Файл:** `twa/src/App.jsx` (состояние: `activeTab`)

Три вкладки, только иконки, в нижней части экрана:
- **Задачи** — иконка чеклиста
- **Цели** — иконка мишени
- **Рутина** — иконка обновления (заглушка, пусто)

Активная иконка: 28px, акцентный цвет. Неактивные: 24px, серые. Плавный CSS-переход.

### 3. Управление задачами

**Файл:** `twa/src/App.jsx`

- Добавление задач: `addTask(text, deadline?, time?)` → сохраняет в Firebase под путём `users/shared_user/tasks/{id}`
- Выполнение задач: `completeTask(id)` → удаляет из списка, увеличивает счётчик `completedToday`
- Закрытие задач: `dismissTask(id)` → удаляет из списка **без** увеличения счётчика (задача пропущена, не учитывается в прогрессе)
- Все авторизованные пользователи видят один общий список задач (захардкожен `userId = 'shared_user'`)

#### Дедлайны

- Клик на поле ввода задачи → под ним появляются поля выбора даты и времени; клик вне — скрываются
- После нажатия `+` или Enter поля скрываются
- Год ограничен 4 цифрами (`max="9999-12-31"`)
- Если дата не выбрана: задача добавляется как обычно
- Если выбрана только дата (без времени): к тексту добавляется ` · ДД.ММ`, в Firebase сохраняется `deadline: "YYYY-MM-DD"`
- Если выбраны дата и время: к тексту добавляется ` · ДД.ММ ЧЧ:ММ`, в Firebase сохраняется `deadline: "YYYY-MM-DDTHH:MM"`
- Цвет фона задачи показывает сколько времени осталось (пересчитывается при открытии/обновлении):
  - Зелёный `rgba(76,175,80,0.25)` — прошло менее 50% срока
  - Жёлтый `rgba(255,193,7,0.3)` — прошло 50–80%
  - Красный `rgba(255,107,107,0.35)` — прошло более 80% или срок истёк
- Плавный CSS-переход: `background-color 0.8s ease`
- Цвет пересчитывается при каждом открытии/обновлении (не в реальном времени)

### 4. Цели / Vision Board

**Файл:** `twa/src/components/GoalsBoard.jsx`

Мозаичная сетка фотографий, где каждая ячейка — одна цель.

#### Раскладка
- CSS Grid, 2 колонки, квадратные ячейки
- Малая ячейка: 1×1 (по умолчанию), Большая ячейка: 2×1 (на всю ширину)
- Каждая ячейка: фото заполняет ячейку, подпись (эмодзи + название) снизу

#### Структура данных цели (Firebase: `users/shared_user/goals/{id}`)
```
id: string
title: string
emoji: string
description: string
deadline: string | null     // "YYYY-MM-DD"
imageBase64: string | null  // JPEG сжато до 1200px, качество 0.85
completed: boolean
order: number               // порядок в сетке
size: 'small' | 'large'
createdAt: string
```

#### Взаимодействия
- **Тап на ячейку** → нижний шит с деталями (редактируемое описание, дедлайн, кнопка «Выполнено»)
- **Тап на ячейку «+»** → форма добавления (название, эмодзи, описание, дедлайн, загрузка фото)
- **Загрузка фото:** сжимается на клиенте через canvas (макс. 1200px, JPEG 85%) перед сохранением как base64 в Firebase
- **Режим «Ред.»** (кнопка в шапке):
  - Drag & drop для перестановки ячеек
  - Кнопка ✕ для удаления цели
  - Кнопка ⊞/⊟ для смены размера ячейки (малая ↔ большая)

#### Футер
- Прогресс-бар + «Целей: N» + «Выполнено: M»

### 5. Обнаружение смены дня

Запускается при монтировании приложения и каждые 60 секунд:
- Сравнивает сохранённую дату (`localStorage.twa_last_date`) с текущей датой
- Если даты отличаются: помечает все невыполненные задачи как `carriedOver: true` (отображаются красным)
- Сбрасывает счётчик `completedToday` на 0

### 6. Прогресс-бары

**Файл:** `twa/src/components/DateBlock.jsx`

- **Прогресс года:** Дни, прошедшие с начала года / дни в году (учитывает високосные годы)
- **Прогресс дня:** Выполненные задачи сегодня / всего задач начато сегодня
- Форматируется как "Пятница, 27 февраля" (русская локализация)

### 7. Интеграция с Telegram ботом

**Файлы:** `twa/api/webhook.py` (Vercel) + `bot.py` (локально)

Два режима работы бота:

1. **Vercel Webhook (продакшн):** `twa/api/webhook.py` работает как Vercel Serverless Function. Telegram отправляет POST-запросы на `https://telegram-to-do-mini-app.vercel.app/api/webhook` при каждом сообщении.
2. **Локальный polling (разработка):** `bot.py` запускается локально командой `py -3.13 bot.py`.

**Схема работы:** Пользователь пишет боту → webhook получает сообщение → записывает задачу в Firebase → слушатель TWA срабатывает → задача мгновенно появляется в UI.

**Endpoint регистрации:** `GET /api/webhook?setup=1` — регистрирует URL webhook в Telegram (вызвать один раз после деплоя).

**Белый список:** Те же `ALLOWED_IDS`, что в `twa/src/auth.js` — только внесённые пользователи могут создавать задачи через бота.

**Переменные среды Vercel (обязательны):**
- `BOT_TOKEN` — токен Telegram бота
- `FB_PROJECT_ID` — ID проекта Firebase
- `FB_PRIVATE_KEY_ID` — ID приватного ключа сервисного аккаунта
- `FB_PRIVATE_KEY` — приватный ключ сервисного аккаунта (в кодировке Base64)
- `FB_CLIENT_EMAIL` — email клиента сервисного аккаунта
- `FB_CLIENT_ID` — ID клиента сервисного аккаунта
- `FB_CLIENT_CERT_URL` — URL сертификата клиента сервисного аккаунта
- `OPENAI_API_KEY` — ключ OpenAI *(нужен для транскрибации голоса, сейчас отключено)*

**Чтобы включить транскрибацию голоса:** добавить `OPENAI_API_KEY` в переменные Vercel и `.env`, затем раскомментировать все блоки `# [VOICE]` в `twa/api/webhook.py` и `bot.py`.

### 8. Синхронизация через Firebase

**Файл:** `twa/src/firebase.js`

- Слушатели в реальном времени для задач, счётчика выполнения и целей
- Структура данных:
  ```
  users/
    shared_user/
      tasks/
        {id}: { id, text, createdAt, carriedOver, deadline? }
      completedToday: {number}
      goals/
        {id}: { id, title, emoji, description, deadline, imageBase64, completed, order, size, createdAt }
  ```
- Слушатели запускаются только после подтверждения аутентификации

## Развёртывание

### Vercel (продакшн)

1. Подключить GitHub репозиторий к Vercel
2. В Vercel Dashboard → Settings → General:
   - **Root Directory:** `twa`
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
3. Добавить все переменные `FB_*` и `BOT_TOKEN` в Settings → Environment Variables
4. Запушить в GitHub — Vercel деплоит автоматически
5. Зарегистрировать webhook один раз: открыть `https://telegram-to-do-mini-app.vercel.app/api/webhook?setup=1` в браузере

### Локальный бот (разработка/альтернатива)

```bash
py -3.13 bot.py
```

Требует `.env` с `BOT_TOKEN` и `FIREBASE_CREDENTIALS_PATH`.

## Важные заметки

- **Общие данные:** Все авторизованные пользователи видят и редактируют одни и те же задачи и цели. Чтобы переключиться на данные отдельного пользователя, измените `userId` с `'shared_user'` на ID аутентифицированного пользователя.
- **Ключи localStorage:**
  - `twa_last_date` — Дата последнего открытия приложения (YYYY-MM-DD)
  - `twa_browser_id` — Введённый пользователем Telegram ID (только браузер)
- **Telegram SDK:** Загружается синхронно в `index.html` перед другими скриптами. Опциональный оператор (`?.`) защищает от отсутствия SDK в обычном браузере.
- **Фото целей:** Хранятся как base64 в Firebase (без внешнего хранилища). Сжимаются до 1200px JPEG 85% ≈ 100–300KB на фото.

## Принадлежность файлов

- **Локальный бот** (`bot.py`, `requirements.txt`, `.env`) — Локальный polling режим. На Vercel не деплоится.
- **Vercel webhook** (`twa/api/webhook.py`, `twa/api/requirements.txt`) — Обработчик бота для продакшна. Деплоится автоматически вместе с TWA.
- **Файлы TWA** (директория `twa/src/`) — Основной фокус. Вся логика аутентификации/задач/целей/синхронизации находится здесь.

## Поведение UI по платформам

### Telegram Mini App
- Автоматическая проверка ID пользователя из SDK
- Страница AccessDenied показывается без кнопки повтора (состояние только для чтения)

- Возможность попробовать другие ID
